# Hospitality Management System

A desktop-based hotel management application developed using **Core Java (Swing)** with **MongoDB** as the backend database. The application uses the **native MongoDB Java Driver** without Spring, Hibernate, ORM tools, Maven, or Gradle.

The project was initially developed using **MySQL and JDBC** and was later migrated to MongoDB as a practical exercise in converting relational-style data into a document-oriented NoSQL structure.

## Features

* **Hotel Management** — Stores hotel name, location, amenities, and room pricing for single, couple, and family categories.
* **Room Management** — Maintains room number, room type, price, hotel association, and availability status.
* **Guest Management** — Stores guest name, email, phone number, and associated Guest ID.
* **Reservation Management** — Handles guest, room, check-in/check-out dates, and total reservation cost.
* **Data Retrieval** — Supports searching by guest name and check-in date while retrieving related guest, reservation, and room information across collections.
* **Single-Window Interface** — Uses Swing `CardLayout` for navigation instead of opening separate windows for each entity. Each screen includes read-only result tables and a "Back to Menu" option.

## Technology Stack

* **Programming:** Java
* **GUI:** Java Swing
* **Database:** MongoDB
* **Database Driver:** MongoDB Java Driver (`mongodb-driver-sync`, `mongodb-driver-core`, `bson`)
* **Development:** JAR dependencies added manually without Maven or Gradle

## Data Model

The application uses four main collections with integer IDs as references rather than embedding related documents.

```text
hotels          { _id, name, location, amenities, singleRoomPrice, coupleRoomPrice, familyRoomPrice }
rooms           { _id, hotelId, roomNumber, type, price, status }
guests          { _id, name, email, phone }
reservations    { _id, guestId, roomId, checkIn, checkOut, totalCost }
counters        { _id, seq }   // Internal collection for auto-incrementing IDs
```

The `rooms.hotelId`, `reservations.guestId`, and `reservations.roomId` fields act as references to documents in other collections. Since MongoDB does not enforce foreign-key constraints, referential checks are handled at the application level through the relevant DAO and GUI logic.

## Key Design Decisions

### References Instead of Embedding

Rooms, guests, and reservations are maintained as separate collections because they are independently queried and updated through their respective GUI screens. This makes references by ID more suitable than embedding documents, such as storing all rooms directly inside a hotel document.

Embedding is used where appropriate. For example, the three room-category prices are treated as a single logical pricing structure rather than unrelated attributes.

### Auto-Incrementing IDs

MongoDB does not provide a direct equivalent to SQL's `AUTO_INCREMENT`. To handle this, the project uses a dedicated `counters` collection.

Each entity type maintains its own counter:

```text
{ _id: "hotelId", seq: N }
```

New IDs are generated by atomically incrementing the counter using `findOneAndUpdate` with `$inc`. This prevents duplicate IDs when multiple inserts occur concurrently.

### Schema Validation

Unlike SQL databases, MongoDB does not enforce document structure by default. To maintain data consistency, each collection uses a `$jsonSchema` validator.

The validators define:

* Required fields
* Data types
* Minimum values
* Valid document structure

For example, negative room prices are prevented at the database level during insert or update operations.

### Indexes

Two indexes were implemented:

* A **unique index** on `guests.email` to prevent duplicate guest records.
* A **compound index** on `reservations (guestId, roomId)` to support common reservation lookups.

### Manual BSON Mapping

Each model class (`Hotel`, `Room`, `Guest`, and `Reservation`) contains its own `toDocument()` and `fromDocument()` methods.

This provides explicit conversion between Java objects and MongoDB `Document` objects without using an ORM or external object-mapping library such as Jackson or Gson.

### Local MongoDB

The project was initially connected to MongoDB Atlas, but the Java MongoDB driver's TLS connection repeatedly failed with an `SSLException: internal_error` in the development environment.

Since `mongosh` could connect successfully to the same cluster, the issue appeared specific to the Java driver's TLS negotiation rather than network connectivity or credentials.

The project was therefore switched to a local MongoDB instance using:

```text
mongodb://localhost:27017
```

This removed the TLS and authentication requirements for local development. The DAO layer remains independent of the deployment environment; only the connection string in `MongoConnectionManager` needs to be changed to reconnect to Atlas.

### Guest–Reservation Linkage

When a reservation is created, a Guest ID is generated automatically using the same counter mechanism used for other entities.

Guest information can then be entered separately through the Guest panel using that Guest ID. This allows a reservation to exist before the complete guest profile has been entered, representing a booking workflow where a room may be held before all guest details are collected.

## Project Structure

```text
src/com/database/
    MongoConnectionManager.java   // MongoClient/MongoDatabase connection
    Counters.java                 // Auto-increment ID generation
    DatabaseSetup.java            // Collection, validation, index setup
    Hotel.java / HotelDAO.java
    Room.java / RoomsDAO.java
    Guest.java / GuestDAO.java
    Reservation.java / ReservationDAO.java
    DAOSmokeTest.java             // End-to-end DAO CRUD verification

src/com/GUI/
    MainGUI.java                  // CardLayout container and menu
    HotelPanel.java
    RoomPanel.java
    GuestPanel.java
    ReservationPanel.java
    RetrieveDataPanel.java        // Cross-collection search
```

## How to Run

1. Install and start MongoDB locally using `mongod`, or change the connection string in `MongoConnectionManager.java` to a remote MongoDB instance.
2. Add the MongoDB Java Driver JAR files (`mongodb-driver-sync`, `mongodb-driver-core`, and `bson`) to the project's build path.
3. Run `DatabaseSetup.java` once to create the collections, schema validators, indexes, and counters.
4. Run `MainGUI.java` to launch the application.
